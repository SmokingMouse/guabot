# Quickstart: LLM 驱动决策与 Tools/Skills 联通验证

本指南面向希望在测试环境中快速验证 “LLM + Tools + Skills” 端到端流程的开发与运维同学。

## 前置条件

- 已拉取 `002-llm-tools-skills` 分支，并完成依赖安装；
- 已在配置中设置好单一 LLM 提供方的访问凭证（如 API Key 或内网网关地址）；
- 至少注册了 1 个可供 LLM 调用的工具/Skill（例如“当前时间”或“错误计数查询”）。

## 步骤 1：启动本地或测试环境服务

1. 在项目根目录激活虚拟环境并启动服务（具体命令以 README 为准，例如）：
   - `cd /home/zhangpeng.pada/python/guabot`
   - `source .venv/bin/activate`
   - 运行提供 IM Webhook 能力的进程（如有专门的 CLI/服务入口）。

2. 确认 IM 平台能将消息推送到 `contracts/llm-tools-flow.yaml` 中约定的 Webhook 地址。

## 步骤 2：通过 IM 发送简单请求

1. 在 IM 中向机器人发送闲聊消息，例如：“讲个笑话”。
2. 预期行为：
   - 机器人回复自然语言笑话；
   - 日志中只记录 LLM 调用，无工具调用记录。

## 步骤 3：触发单步工具调用

1. 在 IM 中发送需要工具支持的消息，例如：“现在时间是多少？” 或 “查一下当前服务状态”。
2. 预期行为：
   - LLM 判断需要调用相应工具；
   - 能力层执行工具并返回结果；
   - 最终回复中包含具体结果（时间或服务状态），而不是泛化描述；
   - 日志中能看到“LLM 决策 → 工具调用 → 工具结果 → 回复”的链路，并附带 `trace_id`。

## 步骤 4：验证多步工具/Skill 编排

1. 在 IM 中发送复合请求，例如：“帮我查一下今天错误数和当前版本，并给个一句话总结”。
2. 预期行为：
   - LLM 至少发起两次不同能力调用；
   - 回复中同时包含两个能力的结果以及一句话总结；
   - 若其中一个能力暂不可用，回复中应说明缺失部分，并继续返回其它可用信息。

## 步骤 5：查看执行轨迹与调试

1. 根据 IM 回复中的 `trace_id`，在日志或调试视图中检索对应的执行轨迹；
2. 确认轨迹中记录了关键步骤：
   - 收到用户消息与会话信息；
   - LLM 请求摘要与选择的工具名称；
   - 每次工具调用的参数摘要、状态和耗时；
   - 最终回复生成与发送结果。

通过以上步骤，可以初步验证本特性“LLM 决策 + Tools/Skills 编排 + 可观测性”的端到端闭环是否工作正常。
